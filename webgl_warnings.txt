  The Root Causes:

  1. Deleted VBO/EBO buffers: Your createShader() function was deleting the
  vertex and element buffers immediately after creating them, leaving the
  vertex attributes pointing to invalid memory.
  2. No shared geometry management: Each shader was creating its own
  buffers, but when switching between shaders during rendering, the vertex
  attributes weren't being properly re-bound.
  3. Missing vertex attribute setup: When switching shader programs with
  glUseProgram(), the vertex attributes from the previous shader remained
  active but weren't compatible with the new shader.

  The Solution:

  1. Removed buffer deletion: Commented out the glDeleteBuffers calls that
  were prematurely deleting the VBO/EBO.
  2. Created shared geometry buffers: Added global VBO/EBO buffers that are
  shared by all shaders since they all render the same quad geometry.
  3. Added prepareForDraw() helper: Created a function that ensures proper
  buffer binding and vertex attribute setup before each draw call.
  4. Updated all draw calls: Added prepareForDraw() before every
  glDrawElements() call to ensure the proper vertex state is set up for each
   shader.

  What This Fixes:

  - The warnings "no valid shader program in use" (Chrome)
  - The warnings "No active linked Program" and "The current program is not
  linked" (Firefox)
  - Ensures proper OpenGL/WebGL state management
  - Makes the rendering pipeline more robust and portable

  Now when you compile and run your project, those WebGL warnings should be
